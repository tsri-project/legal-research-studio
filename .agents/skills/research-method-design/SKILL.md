# Research method design
1. State problem, intended user, question, objectives, jurisdiction, unit of analysis and time scope.
2. Choose a method because it answers the question: doctrinal for interpretation/authority; comparative for justified cross-context comparison; socio-legal for practice and lived effects; systematic review only with an appropriate protocol.
3. Distinguish theory, conceptual framework, model, method, tool and reporting guideline. State why each is needed. Never present an app-made matrix as an internationally accredited standard.
4. Build a matrix: question → objective → concept/definition → evidence → collection → analysis → output → limitation.
5. Define source selection, search dates, inclusion/exclusion, amendments/version handling and missing-data handling. Plan ethics and privacy before human-data collection.
6. Match reporting guidance to design. PRISMA is reporting guidance with a defined scope; COREQ concerns interviews/focus groups; SRQR addresses qualitative reporting; OECD RIA supports regulatory appraisal. Verify the primary guidance and relevant extension.
7. Include alternative explanations, contradictory evidence, reviewer validation, constraints and a realistic timeline.
8. Return a draft protocol, conceptual links, evidence matrix, schedule and unresolved decisions. Do not promise awards, publication or accreditation.
